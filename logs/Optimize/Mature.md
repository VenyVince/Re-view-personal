# Performance Measurement Plan

이 문서는 `Optimize.md`에서 정리한 문제를 기준으로, 성능 개선 전에 먼저 재야 할 정량 지표와 벤치마크 우선순위를 정리한 문서다.

## 정량 측정 항목

### 1. 응답 시간

- 평균 응답 시간
- p95 응답 시간
- p99 응답 시간

### 2. 처리량

- 초당 요청 수 `RPS`
- 분당 처리 요청 수

### 3. DB 비용

- 쿼리 실행 시간
- 반환 row 수
- `SELECT` 횟수
- `COUNT`, `JOIN`, `OFFSET/FETCH`, `LIKE '%...%'` 사용 비중

### 4. 이미지 처리 비용

- 응답당 `presignedUrlGet` 호출 횟수
- 응답당 object key 수
- 이미지 URL 변환 총 시간
- 이미지 포함 응답 payload 크기

### 5. 동시성 비용

- 포인트 `FOR UPDATE` 대기 시간
- 주문 재고 차감 경합 시간
- 트랜잭션 평균 유지 시간

### 6. 메모리 비용

- 응답 생성 중 peak heap 사용량
- 대량 리스트 변환 시 객체 생성 수
- 대량 row 그룹핑 시 중간 컬렉션 크기

### 7. 배치 비용

- 월간 베스트 리뷰 갱신 수행 시간
- 갱신 대상 row 수
- 배치 실행 중 DB 부하

## 벤치마크 우선순위

### 1. 상품 목록 API

- 이유: 가장 기본 화면이고, 페이징 부재와 이미지 URL 변환 반복이 동시에 드러난다.
- 측정 포인트: 상품 수 증가에 따른 응답 시간, payload 크기, URL 변환 횟수.

### 2. 통합 검색 API

- 이유: `LIKE '%keyword%'` 검색과 상품/리뷰 동시 조회가 겹쳐서 부하가 크다.
- 측정 포인트: 키워드별 응답 시간, DB 실행 시간, 검색 결과 수 증가에 따른 변화.

### 3. 상품 상세 리뷰 API

- 이유: 리뷰 row 증폭, 이미지 그룹핑, Presigned URL 변환이 함께 일어난다.
- 측정 포인트: 리뷰 수와 이미지 수에 따른 응답 시간, 반환 row 수, 메모리 사용량.

### 4. 리뷰 목록 API

- 이유: 조인과 OFFSET 페이지네이션이 겹친다.
- 측정 포인트: page 번호 증가에 따른 응답 시간, sort 별 차이, DB 비용.

### 5. MinIO 이미지 발급 API

- 이유: 이미지가 많아질수록 생성 호출이 자주 일어나고, 업로드 전 단계의 체감 성능이 보인다.
- 측정 포인트: 발급 요청당 처리 시간, 동시 요청 시 처리량, object key 생성 비용.

### 6. 마이페이지 리뷰 검색 API

- 이유: 사용자별 데이터라 작아 보이지만, 이미지 조인과 부분 일치 검색이 섞인다.
- 측정 포인트: 사용자별 리뷰 수 증가에 따른 응답 시간, URL 변환 횟수.

### 7. 주문 목록 API

- 이유: 주문 수가 많아질수록 행별 서브쿼리 비용이 보인다.
- 측정 포인트: 주문 건수 증가에 따른 응답 시간, row별 서브쿼리 비용.

### 8. 추천 API

- 이유: 점수 계산과 윈도우 함수가 들어가서 데이터 증가 시 DB CPU 부담이 크다.
- 측정 포인트: 상품/리뷰 수에 따른 응답 시간, DB CPU 시간, 반환 건수.

### 9. 주문 처리 API

- 이유: 트랜잭션, 포인트 차감, 재고 차감이 묶여 있어 동시성 비용을 보기 좋다.
- 측정 포인트: 주문 상품 수 증가에 따른 트랜잭션 시간, 재고 경합, 실패율.

### 10. 월간 베스트 리뷰 배치

- 이유: 사용자 요청 API는 아니지만, 데이터가 커질수록 운영 시간에 영향을 준다.
- 측정 포인트: 실행 시간, 대상 리뷰 수, 배치 동안의 DB 부하.

## 벤치마크 순서

1. 상품 목록 API
2. 통합 검색 API
3. 상품 상세 리뷰 API
4. 리뷰 목록 API
5. MinIO 이미지 발급 API
6. 마이페이지 리뷰 검색 API
7. 주문 목록 API
8. 추천 API
9. 주문 처리 API
10. 월간 베스트 리뷰 배치

## 측정 방식 메모

- 각 API는 최소 3개 데이터 크기 구간으로 나눠 측정한다.
- 가능하면 100건, 1,000건, 10,000건 단위로 증감시킨다.
- 응답 시간은 평균보다 p95를 우선 본다.
- 이미지가 포함된 API는 URL 변환 전과 후를 분리해서 본다.
- 주문과 포인트는 단일 요청보다 동시 요청 상황을 같이 본다.
- 배치는 실시간 API와 분리해서 따로 측정한다.
